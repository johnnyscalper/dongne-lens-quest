# v0.2 검토 구성

요청한 10개 에이전트를 기능 구현과 독립 검토로 나누었습니다. 아래는 담당 범위이며 통과 여부는 [검증 기록](VALIDATION.md)의 실제 실행 결과를 따릅니다. 통합·배포 담당은 이 10개 역할 밖에서 변경을 합치고 원격 업로드 결과를 확인합니다.

| 번호 | 담당 | 산출·검토 범위 |
| --- | --- | --- |
| 1 | 제품·시연 | 두 체험의 의미, 문구, 이름 공개 후 재선택, 60초 시연 |
| 2 | 실험 계산 | 동일 구성 비교, 기간 경계, 블라인드 후보, 가상 연습 예제 |
| 3 | 3D 그래픽 | 입체 마을, 탐험가, 경로, 움직임 제어 |
| 4 | 화면 구조 | 첫 화면, 탐색 흐름, 입체 카드, 반응형 레이아웃 |
| 5 | 실험 클라이언트 | 두 기능 상호작용, 요청 취소, 결과 초기화, 접근 가능한 조작 |
| 6 | 계산 테스트 | 구성 변화, 고정 가중치, 표본 부족, 입력 검증, 후보 재현성 |
| 7 | 데이터·보안 | API 키, 데이터 출처, 부분 조회, 계산 표현, 개인정보 저장 여부 |
| 8 | 새 저장소·Replit 문서 | 실행 구성, README, 시연, 데이터 기준, CI |
| 9 | 접근성·성능 | 키보드, 대비, 움직임 감소, 가벼운 렌더링, 화면 크기 대응 |
| 10 | 최종 UX | 실제 이용 흐름, 시각 검토, 오류·빈 결과·재선택 상태 |

완성도를 높이기 위해 기본 면적을 전체로 두고, 두 변화율의 차이를 인과적인 가격 상승분으로 표현하지 않도록 했습니다. 주소 공개 뒤 다시 선택하는 단계로 이름의 영향을 스스로 돌아보게 합니다.
